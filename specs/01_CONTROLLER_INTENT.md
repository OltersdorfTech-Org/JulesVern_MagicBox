# 01_CONTROLLER_INTENT.md
**Jules Verne Magic Box — Controller Intent (Authoritative Spec)**

## Purpose
This system is an **interactive appliance with a web UI** that controls a physical “magic box” artifact. It must be **boringly reliable** and **deterministic**.

## Core principle
If the Pi boots successfully but Wi‑Fi, web UI, or logs are unavailable, the system must still communicate health via the **Status LED blink codes**.

## Target platform (locked)
- Hardware: **Raspberry Pi Zero 2 W**
- OS: **Raspberry Pi OS (64‑bit), Debian Trixie–based**
- Runtime: **System Python 3** (no venv, no containers)
- Service manager: **systemd**
- Normal operation: **headless**
- Networking: **assumed to exist**; the system must **not** attempt to configure Wi‑Fi/AP/credentials

## Interfaces
### Physical Inputs (GPIO → GND, internal pull‑ups)
- Lid switch (NO)
- Key 1 switch (NO)
- Key 2 switch (NO)

### Physical Outputs (GPIO → resistor → LED → GND)
- Status LED (health/fault)
- Message/Indicator LED
- Key 1 LED
- Key 2 LED
- Magic LED

### Web UI Inputs
- Toggle: **Message/Object Received** (I4)
- Toggle: **GPIO Enable/Disable** master gate (I5)
- Action: **Show Logs** (I7)
- Action: **Export Logs** (I6)

## Non‑goals (v1)
- No remote access beyond local LAN
- No pin reassignment UI
- No dynamic configuration for GPIO mapping
- No images/diagrams generated by Codex (placeholders only)

## Success criteria
- Cold boot → Status LED indicates booting then ready
- Web UI reachable on LAN
- Switch actions drive LEDs as defined in `03_BEHAVIOR_TRUTH_TABLE.md`
- All faults are visible via Status LED and written to persistent logs
- Logs are exportable to `/boot/firmware` for Windows access
